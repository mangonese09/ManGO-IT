# ManGO:IT — Adversarial Visual & Interaction QA — REPORT (v0.9.2, 2026-07-27)

## Verdict

This is functionally solid — no crashes, no XSS, no undefined-on-screen, honest degraded labeling — but visually it is a competent utility, not Kayak. Three systemic gaps produce most of the distance: (1) **no enforced scale** — 28 distinct font sizes from compounding `em`s, off-grid paddings (10/14/18px everywhere), and two phantom CSS vars silently hardcoding colors; (2) **mango is not rare** — the Home screen shows five-plus mango elements competing, so the one action that should pop (Find routes) doesn't; (3) **the primary number is not sacred** — the clock pair wraps when a day tag + walk chip crowd it, the walk chip itself collapses into a circle, and muted meta text fails contrast so hierarchy is by illegibility instead of by design. Close those three and the app reads like a designed product; the rest is line items.

## The three changes that close most of the gap

1. **Adopt a hard scale and delete the drift (QA-09, 10, 13, 21):** 6 rem font sizes, 4-px spacing grid with a 16px rail, radii {12,16,999}, and kill the two phantom vars. One CSS pass, app-wide payoff.
2. **Make mango rare (QA-11):** neutral chrome for toggles and the direct block; mango = Find routes + live pulses only. Instant hierarchy.
3. **Protect the clock line (QA-02, 22, 05):** nowrap chip, "+1" day badge, reserved results space. The primary number never wraps, never shifts, never shares its line.
